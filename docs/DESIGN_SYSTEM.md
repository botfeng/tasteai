# TasteAI 设计规范 · Day 0

## 范围与依据

TasteAI 是中文菜谱推荐网站，面向纠结「今天吃什么」的普通用户，不是外卖商城或企业后台。界面以简体中文为主，品牌、技术名称允许少量英文；源码使用英文命名。

视觉依据为《TasteAI_项目执行手册_含UI_Skill与产品脚本.md》第 2 节与同目录的 `ui-reference.png`。参考图仅用于观察色彩、留白、圆角与轻盈感，不截取其中图片，也不引入购物车、价格或营养诊断功能。

本阶段仅提供工程启动页、真实服务连接检查与基础样式。不制作业务页面、菜谱数据、数据库、反馈机制或推荐算法。

## Skill 使用规则

- 官方来源：https://github.com/nextlevelbuilder/ui-ux-pro-max-skill
- 安装器：`ui-ux-pro-max-cli@2.15.0`；使用 `uipro init --ai qoder`。
- 项目入口：`.qoder/skills/ui-ux-pro-max/SKILL.md`。
- 后续 UI/UX 工作先调用此 Skill，再结合本规范与参考图筛选建议。
- 实际运行了 `recipe cooking warm minimal` 与收窄后的 `recipe cooking clean minimalist` 设计系统检索；两次均返回 Claymorphism。该风格的厚边框、双重阴影、绿色主操作及英文字体不符合项目要求，未采用或原样持久化。
- 采用通过 `--stack html-tailwind` 查询的 Tailwind 4 CSS-first 语义令牌，以及 React 请求清理、键盘焦点、对比度和减少动态效果原则。
- Skill 的检索结果不能覆盖本项目明确的视觉与阶段约束；不为套用建议安装额外图标、字体或动画库。

## 色彩

令牌实现在 `frontend/src/styles/index.css` 的 `@theme` 中，组件通过语义工具类引用。

| 用途 | 色值 | 令牌 |
| --- | --- | --- |
| 暖白背景 | `#FFFCF7` | `background` |
| 白色卡片 | `#FFFFFF` | `surface` |
| 温暖橙色主操作 | `#F58A24` | `primary` |
| 悬停与按下 | `#E77A13` | `primary-hover` |
| 柔和橙色底 | `#FFF1DF` | `primary-soft` |
| 主要文字／橙色按钮文字 | `#252525` | `foreground` |
| 次要文字 | `#736E68` | `muted` |
| 轻分割线 | `#F0ECE6` | `border` |
| 橙色强调文字／焦点环 | `#A94D0B` | `accent-text` / `focus` |
| 成功装饰色 | `#47946B` | `success` |
| 成功状态文字 | `#286543` | `success-text` |
| 错误状态文字 | `#A63D2B` | `error` |

界面至少 80% 保持明亮中性色。橙色用于操作和少量强调，不铺大面积渐变。主橙色上不使用白色小字；正文目标对比度至少 4.5:1，焦点环至少 3:1。较手册初始值略加深次要文字，并区分成功装饰色与成功文字色，以满足可读性目标。状态同时使用文字说明，不仅靠颜色区分。

## 字体与空间

- 中文系统字体栈：`"PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif`；不下载外部字体。
- 页面主标题：手机 36px / 宽屏 48px，700 字重；卡片标题 24px / 600；正文 16px；辅助文字 14px。中文行高约 1.6–2。
- 间距使用 4px 基准，常用 8 / 12 / 16 / 24 / 32 / 40 / 56px。
- 卡片圆角 20px，按钮 14px，短标签 999px；卡片阴影 `0 8px 28px rgb(67 42 12 / 6%)`。
- 优先 390px，验证 360 / 390 / 430 / 768 / 1280px；页面边距手机 24px、宽屏 40px。
- Day 0 启动页最大宽度 1024px，768px 以下纵向排列，其上介绍与连接卡片双列。正式业务页可在后续采用手册的 1180px 最大宽度，不直接横向拉伸手机页面。

## Day 0 页面线框

```text
手机：品牌 + 简短标语
      阶段说明
      「先把厨房准备好。」
      简介 + 工程骨架标识
      连接检查卡片
        前端状态
        后端真实连接状态
        状态说明
        重新检查连接按钮
      后续功能边界说明

桌面：品牌 + 标语
      左侧介绍       右侧连接检查卡片
      底部阶段边界说明
```

「先把厨房准备好」是工程初始化的美食主题表达，不冒充已完成产品。唯一操作为重新请求 `/api/health`。

## 组件与交互

- 卡片用白底、20px 圆角、细浅分割和轻阴影；避免厚黑框、玻璃拟态与双重阴影。
- 按钮最小高度 48px；使用原生 `button`，支持 Tab、Enter 和 Space。悬停／按下改变填充色，不移动布局；焦点为 2px 深橙色外环，偏移 4px。
- 请求期间按钮禁用并显示「正在检查…」；成功显示「服务已连接」；失败提示检查本地 8000 端口并允许重试。
- 连接检查超时为 5 秒，卸载时取消请求。结果区域使用 `role="status"` 与礼貌播报。
- 仅使用 200ms 颜色过渡；`prefers-reduced-motion` 时关闭过渡；不使用自动轮播或持续动画。
- Day 0 仅浅色主题，不实现深色主题切换。

## 素材与后续边界

Day 0 未引入任何外部美食摄影、商业字体或图库素材。`frontend/public/favicon.svg` 为本项目现场绘制的餐盘与餐叉矢量标识，仅作品牌占位。

Day 1–2 才开始引导、首页、发现、详情、收藏与口味页面；外部摄影必须逐张核实许可、作者和菜品对应关系，并建立素材台账。禁止裁剪参考图作为页面素材，禁止用不对应的菜图填满界面。图标届时采用手册指定的一套线性 SVG 图标，不混用多套风格。
